## 1. システム概要

### 1.1 目的

診療所における職員のシフト作成を自動化し、各時間帯・各業務における職員のスキルバランスを最適化する。受付業務においては医事業務（保険登録、会計など）の能力を優先してシフトを組む。

### 1.2 対象施設・対象ユーザー

| 項目 | 内容 |
|------|------|
| 施設タイプ | 診療所（リハ室 + 受付）。日勤のみ（夜勤なし） |
| 職員数 | 正職員 + パート職員 合計 5〜10 名程度 |
| 業務エリア | リハ室、受付 |
| 優先業務 | 医事業務（保険登録、会計など） |
| 対象ユーザー | シフト作成を担当する管理者（v2 では管理者のみ。スタッフ向け機能はスコープ外） |

### 1.3 v1 からの再構築の経緯

v1（shift-scheduler-claude）は「複数の拘束時間・休憩パターン（拘束 9〜10 時間、休憩 60〜120 分、2 時間連続休憩など）」を前提に構築された。その後、勤務形態を「9 時間勤務（拘束）・1 時間休憩・実働 8 時間」に統一する方針へ変更されたため、前提となる勤務体系そのものが変わることから、本リポジトリ（v2）で新規に再構築する。

本書は v1 の要求事項定義書（v1.4.0）を元ネタとし、各要件を「維持 / 廃止 / 改訂」に仕分けした上で、v2 の要求事項として再定義したものである。

## 2. v1 からの変更方針（仕分けサマリ）

v1 要件の仕分け結果の全体像。詳細は各章に記載する。

| 区分 | 対象 |
|------|------|

## 3. 設計方針: 設定駆動（ハードコード禁止）【確定】

### 3.1 原則

**診療所固有の事項をソースコードにハードコードしてはならない。** 以下に挙げる事項は、設定ファイル（YAML/JSON 等。形式は技術選定時に決定）で定義し、コード変更なしに切り替え可能に設計する。

- 診療時間（曜日別の午前・午後診療時間、休診日）
- 業務エリアと時間帯別必要人数
- 職種構成（職員タイプと配置可能エリア）
- 勤務体系（拘束時間・休憩時間・休憩回数）
- 休憩タイミング（取得可能時間帯・交代制ルール）
- 変則日の扱い（水曜短縮・土曜延長・半日診療日の勤務時間）
- 週 40 時間チェックの ON/OFF

### 3.2 未確定事項と設定項目の関係

要求提供者への確認待ち項目（[10. 要確認リスト](#10-要確認リスト)）は、**そのまま設定項目の初期値として機能する**よう設計する。すなわち:

- 未確定事項も暫定値を初期値として設定項目に落とし込み、実装を先行できるようにする
- 確認の回答が得られた時点で、コード変更ではなく**設定初期値の更新のみ**で反映を完了できるようにする
- 設定可能項目の全体像は [9. 設定可能項目一覧](#9-設定可能項目一覧) に集約し、未確定のものは「要確認・設定化予定」と明記する

### 3.3 適用範囲の目安

| 区分 | 扱い |
|------|------|
| 診療所固有の値（診療時間・人数・勤務体系等） | 設定ファイルで定義（ハードコード禁止） |
| アルゴリズムの普遍的ロジック（最適化目標・制約の骨格） | コードで実装（制約の重み等の調整値は設定化を検討） |
| 法令由来の固定値（週 40 時間等） | 定数として保持してよいが、チェックの有効/無効は設定化 |

## 4. 新勤務体系の定義【確定】

v2 の勤務体系は以下のとおり確定とする（値は設定ファイルで定義する。3 章参照）。

### 4.1 終日勤務（正職員）

| 項目 | 内容 |
|------|------|
| 拘束時間 | 9 時間 |
| 休憩 | 1 回・1 時間（60 分） |
| 実働時間 | 8 時間 |

### 4.2 v1 から廃止する休憩・勤務ルール

以下の v1 ルールは、新勤務体系では前提が消滅するため廃止する。

- 拘束 10 時間・休憩 120 分の勤務パターン（v1 の「通常」「遅出」に相当）
- 「休憩は基本的に 2 時間連続で取得」の原則
- 「忙しい日は休憩を分割することもある（当日の判断）」の運用
- 緊急時の休憩短縮対応（120 分休憩を 60 分に短縮し、短縮分を残業計上するルール）
- 拘束時間・休憩時間が勤務パターンごとに異なる体系（60 分/120 分の混在）

### 4.3 半日診療日・短縮診療日の勤務（暫定）

木曜・土曜（午前のみ診療）および水曜（午後短縮）の勤務時間定義は未確定である（Q-03・Q-04）。確認完了までの暫定方針は以下とし、設定項目の初期値として保持する。

- 木曜・土曜: v1 同様、半日勤務（4 時間程度・休憩なし）を想定
- 水曜: 終日勤務日として扱い、拘束時間の短縮有無を確認中

### 4.4 出退勤時刻のバリエーション（未確定）

v1 では正職員に早出・通常・遅出の時差出勤（出勤 08:30/08:45/09:15 など）を日ごとに変動割り当てしていた。v2 の統一勤務体系（9 時間拘束）における時差出勤の要否・出退勤時刻の定義は未確定である（Q-05）。

## 5. 診療時間と業務エリア

内容は v1 を維持する。ただし v1 では「システムで固定・ユーザー変更不可」であったのに対し、v2 では**設定ファイルで定義**する（3 章の設定駆動方針による改訂）。画面からの変更は引き続き不可とする。

### 5.1 診療時間（v1 維持・設定化）

以下を設定項目の初期値とする。

| 曜日 | 午前診療 | 午後診療 | 備考 |
|------|---------|---------|------|
| 月曜 | 09:00-12:30 | 15:30-18:30 | 通常診療 |
| 火曜 | 09:00-12:30 | 15:30-18:30 | 通常診療 |
| 水曜 | 09:00-12:30 | 15:30-17:30 | 午後は 1 時間短縮 |
| 木曜 | 09:00-12:30 | 休診 | 午前のみ |
| 金曜 | 09:00-12:30 | 15:30-18:30 | 通常診療 |
| 土曜 | 09:00-13:30 | 休診 | 午前のみ（延長） |
| 日曜 | 休診 | 休診 | 定休日 |

### 5.2 業務エリアと必要人数（v1 維持・設定化）

#### リハ室

- **業務時間**: 08:30〜19:00
- **必要人数**:
  - 午前開始時（9:00）: 2 名
  - 12:00〜13:30: 1 名
  - 13:30〜15:30: 無人可（0 名でも可）
  - 午後開始時（15:30）: 2 名
  - 17:30 以降: 1 名
- **スキル要件**: リハ助手スキル

#### 受付（事務）

- **業務時間**: 08:30〜19:00
- **必要人数**:
  - 午前開始時（9:00）: 3 名
  - 12:00〜13:30: 2 名（標榜診療時間終了後）
  - 13:30〜15:30: 2 名
  - 午後開始時（15:30）: 3 名
  - 17:30 以降: 3 名
- **スキル要件**: 受付スキル（医事業務能力を優先）

> **注**: v1 文書内には受付必要人数について「午前 3 名/午後 3 名」（時間帯定義）と「午前 4-5 名/午後 3 名」（休憩制約の記述）の 2 通りの記載があり不整合がある。v2 では上記の時間帯定義を暫定初期値とするが、正しい必要人数は確認中である（Q-06）。

### 5.3 休憩中の窓口維持（v1 維持・数値は要確認）

- 受付に配置された職員が休憩を取る場合でも、窓口には必要人数が残ること
- 休憩は交代制で取得する（同時に複数名が休憩に入らない）

## 6. 機能要件

各機能の v1 からの扱い（維持 / 廃止 / 改訂 / 新規）を明示する。

### 6.1 機能一覧と仕分け

| ID | 機能 | v1 からの扱い | 内容 |
|----|------|--------------|------|
| FR-01 | 職員情報管理 | 維持（一部改訂） | 職員タイプ、スキルスコア（4 項目）、勤務形態の登録・管理。勤務形態は新体系に合わせ簡素化 |
| FR-02 | 休暇管理 | 維持 | 日付単位の休暇登録（終日・午前休・午後休） |
| FR-03 | 自動シフト最適化 | 維持 | 3 つの最適化モード（バランス / スキル重視 / 日数重視） |
| FR-04 | 休憩時間自動割り当て | 改訂 | 「1 回・1 時間」前提に再設計。交代制で窓口必要人数を保証 |
| FR-05 | シフト表示・編集 | 維持 | 生成結果の表示と手動編集 |
| FR-06 | Excel 出力・印刷 | 未確定 | 要否・優先度を確認中（Q-01） |
| FR-07 | 週 40 時間チェック | 改訂（オプション機能） | オプション機能として設計する。初期状態は OFF とし、設定で有効化可能とする |
| FR-08 | 勤務表 CSV 読み込み | 未確定 | v1 で存在した記号体系の再定義が前提（Q-07） |

### 6.2 職員管理（FR-01）

#### 職員タイプ（v1 維持・構成は要確認）

職員タイプによって配置可能な業務エリアが制限される。職種構成は設定ファイルで定義し、以下の v1 構成を暫定初期値とする。

| 職員タイプ | 説明 | 配置可能エリア |
|-----------|------|---------------|
| TYPE_A | オールラウンダー | リハ室・受付両方可能 |
| TYPE_B | 受付専任 | 受付のみ |
| TYPE_C | リハ室専任（正職員） | リハ室のみ |
| TYPE_D | リハ室専任（パート） | リハ室のみ |
| TYPE_E | 受付専任（パート） | 受付のみ |
| TYPE_F | 受付専任（時短） | 受付のみ |

職種構成が v1 時点から変化している可能性があるため、タイプ構成は確認中である（Q-02）。

#### スキルスコア（v1 維持）

各職員は以下 4 項目のスキルスコアを持つ（0〜100 点）。

| スキル項目 | 説明 |
|-----------|------|
| リハ室スキル | リハビリ室での業務能力 |
| 受付午前スキル | 受付業務（午前）の能力（医事業務を優先） |
| 受付午後スキル | 受付業務（午後）の能力（医事業務を優先） |
| 総合対応力 | 全般的な対応能力 |

#### 勤務形態マスタ（改訂）

- v1 の勤怠管理システム連携前提のコード番号体系（0/100/200/300/400/500/900 番台、コード 001〜907）は**廃止**する
- v1 の事務課/看護課の 2 系統分類・看護課別画面は**廃止**する（看護職のシフトを v2 で扱うか否かは Q-02 で確認）
- v2 では新勤務体系（9 時間拘束・1 時間休憩）を基本とし、パート・時短等のパターンは確認結果（Q-08）を踏まえて設定ファイルで定義する
- 正職員は「日によって割り当てが変動」、パート・時短は「登録された勤務形態で固定」という v1 の割り当て方針は**維持**する

### 6.3 休暇管理（FR-02・v1 維持）

| 種別 | 説明 | 影響範囲 |
|------|------|---------|
| 終日休暇 | 1 日全体の休暇 | その日の全時間帯が勤務不可 |
| 午前休 | 午前のみの休暇 | 午前の時間帯のみ勤務不可 |
| 午後休 | 午後のみの休暇 | 午後の時間帯のみ勤務不可 |

- 休暇登録のない日は、勤務形態に応じて自動的に勤務可能と判定する
- 有給休暇の種別管理は行うが、v1 の勤怠管理システム有休コード（901〜907）の保持は廃止する

### 6.4 シフト最適化（FR-03・v1 維持）

#### 最適化モード

| モード | 説明 | 使用場面 |
|--------|------|---------|
| バランス | 勤務回数とスキルの両方を考慮（推奨） | 通常運用 |
| スキル重視 | 目標スキルスコアへの近似を優先 | スキルバランスが重要な時期 |
| 日数重視 | 勤務回数の均等化を優先 | 負担の平準化を重視する場合 |

#### 最適化目標

- **スキルバランスの最適化**: 各時間帯に配置される職員のスキル平均を目標値に近づけ、日によるサービス品質のバラツキを防ぐ。受付業務では医事能力を優先する
- **勤務回数の均等化**: 各職員の勤務回数を可能な限り均等にし、特定職員への負担集中を防ぐ

#### 制約条件の方針

- ハード制約（休暇日に勤務させない、配置不可エリアに配置しない、各時間帯の必要人数充足、終日勤務の原則）は v1 の考え方を維持する
- 休憩関連の制約は新勤務体系（1 回・1 時間、交代制、窓口人数保証）に合わせて改訂する
- 制約が参照する診療所固有の値（必要人数・診療時間等）は設定ファイルから読み込む（3 章）
- 制約の完全な一覧（ID・優先度・根拠付き）は本書確定後に別文書 `CONSTRAINTS.md` として作成する

### 6.5 休憩時間自動割り当て（FR-04・改訂）

システムが以下を満たすよう休憩を自動割り当てする。

- 終日勤務者に 1 時間×1 回の休憩を割り当てる（分割なし）
- 受付窓口の必要人数を常時保証する（交代制）
- 休憩時間帯の候補（診療時間との関係でいつ取得可能か）は設定項目とし、初期値は確認中である（Q-04）

### 6.6 週 40 時間チェック（FR-07・オプション機能）

- 週法定労働時間（40 時間）のチェック機能を**オプション機能**として設計する
- **初期状態は OFF** とし、設定で有効化できること（ON/OFF は設定項目。3 章）
- 有効時は、シフト生成結果に対して週 40 時間超過の警告を表示する

## 8. スコープ外

以下は v2 のスコープ外として明示的に除外する。

| 項目 | 内容 | 理由 |
|------|------|------|
| スタッフ向け機能 | 希望提出・シフト確認・交代申請（v1 評価で指摘されたスタッフ向け機能一式） | 当面不要と決定済み。v2 は管理者専用システムとする |
| 36 協定対応 | 時間外労働の記録・上限チェック | 不要と決定済み |
| 夜勤関連制約 | 夜勤インターバル・連続夜勤禁止等 | 対象施設は日勤のみのため設計から除外 |
| 複数施設対応 | 施設をまたぐシフト管理 | 対象は単一施設のみ |

> **補足**: スタッフ向け機能・36 協定対応は、v1 の多角的評価では「リリース前に解消すべき課題」とされていたが、v2 では要求提供側の裁定によりスコープ外と確定した。将来要望が生じた場合は別途要件定義からやり直す。
